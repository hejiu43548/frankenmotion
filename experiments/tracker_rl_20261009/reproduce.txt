REPRODUCTION NOTES (work in progress; final selected policy pending)

Use the repository source commit and requirements-tracker-rl.txt together.
All commands below run from the repository root. Set experiment-specific paths
explicitly instead of relying on server defaults in the example YAML files.
There are three environments: official generator, GMR retargeter, and RL/native
MuJoCo evaluation. Do not merge their MuJoCo dependencies silently.

1. Reference generation
   GENERATOR_PYTHON scripts/generate_tracker_corpus.py repository=GENERATOR_REPO \
     checkpoint_directory=OFFICIAL_CHECKPOINT_DIR \
     prompts=experiments/tracker_rl_20261009/prompts output=ARTIFACTS/human
   The official checkpoint digest is enforced in corpus.yaml. 20 prompts x
   8 seeds = 160 six-second references; split definitions are explicit.
   This stage may require the original generator's model/text encoder assets.

2. Uniform retargeting
   RETARGET_PYTHON scripts/retarget_tracker_corpus.py \
     manifest=ARTIFACTS/human/manifest.json output=ARTIFACTS/retarget \
     gmr=GMR_SOURCE dependencies=GMR_DEPENDENCIES
   human_height=1.3725929260253906 metres reproduces the original shoulder-to-ankle
   scale metadata. No original specialist policy or skeleton file is needed.
   Source archives are located beside their manifest and checked by SHA-256.
   GMR upstream: https://github.com/YanjieZe/GMR
   The server's GMR directory is an unpacked snapshot, not a Git checkout.
   Its exact source/assets must be bundled or hash-verified, not attributed to
   the unrelated enclosing repository commit returned by git rev-parse.

3. Training robot scene and motion FK
   RL_PYTHON scripts/export_tracker_scene.py output=ARTIFACTS/scene
   RL_PYTHON scripts/prepare_tracker_motion.py root=ARTIFACTS
   The bundled 8KB two-frame fixture supplies upstream environment shapes for scene creation;
   none of its motion frames enter the training dataset. Prepared references
   can subsequently bootstrap scene creation too. Keep the original scene file
   and hash when reproducing the reported experiment.
   RL_PYTHON scripts/audit_tracker_references.py artifacts=ARTIFACTS
   No quality-based filtering was performed in this study.

4. Online RL (random initialization, no action labels)
   RL_PYTHON scripts/train_tracker_rl.py artifacts=ARTIFACTS \
     experiment=baseline_current iterations=3000 num_envs=400 seed=51001
   RL_PYTHON scripts/train_tracker_rl.py artifacts=ARTIFACTS \
     experiment=preview_future iterations=3000 num_envs=400 seed=51001 \
     preview_offsets=[5,10,20]
   RL_PYTHON scripts/train_tracker_residual.py artifacts=ARTIFACTS \
     experiment=reference_residual iterations=3000 num_envs=400 seed=51001
   Each initial comparison consumes 28.8 million environment transitions.
   Reward terms and weights are identical; residual action mapping preserves
   actual motor commands in action history and the action-rate reward.
   Set a NEW experiment name for every fresh run; outputs refuse overwrite.
   To extend a completed own PPO run (fresh simulator/RNG state):
   RL_PYTHON scripts/continue_tracker_rl.py parent_report=PARENT_REPORT \
     checkpoint=PARENT_CHECKPOINT experiment=NEW_NAME iterations=3000 seed=51001
   Data, source semantics, dependency versions, checkpoint digest and restored
   actor/critic/normalizer/optimizer state are checked. This is a new segment,
   not bitwise recovery of an uninterrupted training process.

5. Validation
   RL_PYTHON scripts/evaluate_tracker_rl.py artifacts=ARTIFACTS \
     checkpoint=CHECKPOINT output=NEW_OUTPUT preview_offsets=[5,10,20]
   Add +reference_residual=true for the residual policy checkpoint.
   Use split=val during selection. Test is reserved until recipe selection.
   Training environments sample random reference starts; evaluation always
   begins at reference frame zero and never rescues a failed rollout.

6. Portable inference and fair baseline comparison
   RL_PYTHON scripts/export_tracker_rl.py artifacts=ARTIFACTS \
     checkpoint=CHECKPOINT output=EXPORT_DIRECTORY preview_offsets=[5,10,20]
   Add +reference_residual=true for residual exports. policy.pt emits ordinary
   normalized motor targets, so deployed inference needs no special wrapper.
   RL_PYTHON scripts/evaluate_tracker_cpu.py artifacts=ARTIFACTS \
     policy=EXPORT_DIRECTORY/policy.pt contract=EXPORT_DIRECTORY/contract.json \
     scene=EXPORT_DIRECTORY/scene.mjb output=NEW_OUTPUT
   Evaluate old shared20 separately with policy_kind=shared20 and its verified
   ABI contract. It is NEVER loaded by the training process.
   RL_PYTHON scripts/render_tracker_comparison.py artifacts=ARTIFACTS \
     scene=EXPORT_DIRECTORY/scene.mjb rollouts=NEW_OUTPUT output=VIDEO_DIRECTORY
   Videos replay stored physical states. Early failures hold the last recorded
   frame with an explicit termination label; no fabricated successful tail.

Known reproducibility limits
- GPU simulation is not promised bitwise deterministic across hardware.
- Native MuJoCo and Warp kinematics/termination timing differ slightly; all
  headline old/new policy comparisons must use the same native evaluator.
- Dataset seeds are disjoint, but task descriptions are shared across splits.
- Completion is physical tracking completion, not proof of prompt semantics.
- Reference alignment occurs once per clip; no per-frame floor correction.

Single-reference follow entry
   RL_PYTHON scripts/follow_tracker_rl.py reference=PREPARED_REFERENCE_NPZ \
     policy=EXPORT_DIRECTORY/policy.pt contract=EXPORT_DIRECTORY/contract.json \
     scene=EXPORT_DIRECTORY/scene.mjb output=NEW_OUTPUT
   This accepts the same 50Hz prepared motion arrays and uses the identical
   native evaluator dynamics. A real validation clip produced exactly matching
   states and actions in single-reference and batch modes (follow_parity.json).
   The old SONIC 2350-dimensional policy ABI is a different policy format. Do not
   substitute the new TorchScript file into that old runner without its contract.

Environment separation
- requirements-tracker-rl.txt: online training/export and complete experiment tools.
- requirements-tracker-runtime.txt: CPU inference/evaluation/rendering; no mjlab.
- requirements-tracker-retarget.txt: separate GMR environment, MuJoCo 3.14.0.
  Do not install it over the tracker environment, which uses MuJoCo 3.5.0.
- Official generator remains its separate original environment. The bundled
  fixed corpus allows reproduction of tracker training without regenerating it.
  Reproducing text-to-motion generation additionally needs the official assets.

Observation reconstruction audit
   RL_PYTHON scripts/audit_tracker_observations.py artifacts=ARTIFACTS \
     export=EXPORT_DIRECTORY output=NEW_AUDIT_JSON
   Reconstructs raw current/future observations in native MuJoCo from actual
   GPU rollout states at several times across all validation clips. This checks
   observation semantics, not equivalence of the two physics integrators.

Exact terminal-state diagnostic
   RL_PYTHON scripts/audit_tracker_termination.py artifacts=ARTIFACTS \
     evaluations=[EVALUATION_DIRECTORY_NAME] tasks=[jump,kick,strike] \
     output=NEW_DIAGNOSTIC_JSON
   Replays existing native metrics with their recorded policy and conditions;
   requires every episode metric to match exactly before reporting post-step
   ankle/wrist heights. Uses the same current-reference-index convention as the
   evaluator. It does not relax termination or write training data. Saved config
   paths must resolve on the machine running the audit. Default config uses only
   validation evaluations; do not use test diagnostics while selecting a model.

Explicit initial state and existing simulation integration
   Add initial_state=INITIAL_NPZ to scripts/follow_tracker_rl.py to preserve the
   supplied MuJoCo qpos and qvel. Missing qvel means zero velocity. The caller
   must align reference and initial state in world coordinates. Omitting this
   option retains the reference-start benchmark exactly. No pose snapping is
   applied to supplied states; arbitrary-pose recovery is not established.
   For SONIC+PPO also pass policy_kind=sonic_rl and
   legacy_contract=EXPORT_DIRECTORY/sonic_contract.json.
   RL_PYTHON -m shared_motion.tracker.simulate \
     --actor EXPORT_DIRECTORY/policy.pt --scene EXPORT_DIRECTORY/scene.mjb \
     --contract EXPORT_DIRECTORY/contract.json --reference PREPARED_REFERENCE_NPZ \
     --initial-state INITIAL_NPZ --output NEW_ROLLOUT_NPZ
   Schema 2 selects the new contract-aware native tracker automatically. The
   old contract remains on the historical implementation. New-policy termination
   follows the common native tracking protocol, not the historical fall-only
   rule. Saved trajectories are pre-control states; use final_state.npz (Hydra)
   or <output_stem>_final_state.npz (compatibility entry) for the actual post-step
   state. Each new invocation resets policy history.
   follow_integration_audit.json records exact reproduction of 40 validation
   episodes each for scratch and SONIC+PPO, plus explicit-state API/CLI parity.
   All 14 real unit/integration tests passed. This is interface validation only.

Validation-only checkpoint selection
   RL_PYTHON scripts/select_tracker_checkpoint.py \
     --config-dir ../experiments/tracker_rl_20261009 \
     --config-name selection_extension_config output=NEW_SELECTION_JSON
   The saved example lists all seven completed extension candidates and exactly
   reproduces checkpoint8999 and its full ranking. Paths are machine-specific;
   update them when moving artifacts. For each other run, supply the candidate
   list and exact expected_iterations from final_selection_protocol.txt only
   after all declared checkpoints have native validation results.
   Selection rejects missing/duplicate candidates, test or perturbed metrics,
   mismatched scenes/references/seeds/horizons, and changed policy bytes. Output
   includes metrics/policy/contract/checkpoint hashes and refuses overwrite.
   Historical screening contracts lack embedded policy hashes: those policies
   are still checked directly against the stored evaluation hash, with the
   legacy limitation recorded explicitly. Schema2 requires the embedded hash.
   selection_script_audit.json records seven real candidates and six rejected
   invalid inputs; tests/test_tracker_selection.py checks the tie-break order.
