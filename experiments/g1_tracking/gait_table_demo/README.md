# G1 gait and table-contact demo

This experiment improves the previous table demo's compressed, ground-hugging gait while retaining a single deployed tracker. The existing FrankenMotion goal-conditioned generator is unchanged in this revision. The selected tracker is distilled from offline SONIC walking / prior interaction teachers, followed by DAgger. Inference uses **one fixed 361-input actor**: no routing, weight blending, or teacher calls.

## What generates the motion

Known table pose → walk distance/direction command → FrankenMotion → uniform GMR → reference-only temporal resampling → smooth stop and scene-aware right-arm IK → shared tracker → MuJoCo physics.

**Hand placement is not purely generated by FrankenMotion.** Its reach command is fixed at 0.45 m (human-motion amplitude) as a pose prior. Explicit IK uses a table-relative hand target and an authored lift/extend/lower/hold trajectory. Walk reference timing follows `clip(distance / .45 + .8, 2.8, 4.8)` seconds; rendering remains at 1× speed. Actual robot states are set only at initialization, then produced by policy outputs and physics.

## Results and limitations

After freezing the actor, 32 fresh random layouts each succeeded in GPU and independent CPU execution. Mean GPU walking-goal error: 2.99 cm; hand-target error: 2.68 cm; minimum consecutive sampled tabletop contact: 4.62 s. All 64 trajectories were audited and their actions checked against the same exported actor.

Six paired development scenes improved knee-motion/reference amplitude from 41.3% to 98.6%, and foot-clearance 95th percentile from 0.52 to 2.66 cm. Contact slip remained similar (4.39 → 4.70 cm/s); endpoint precision decreased slightly. These are engineering diagnostics, not a validated perceptual naturalness score. Visual review covered sampled walking, stopping and contact phases for all 32 scenes, with denser representative foot views. Arms remain relatively stiff with mild backward lean near stopping.

Known simulator table pose, stopping distances 0.85–1.75 m, directions ±0.5 rad, tabletop height 0.8 m, nominal physics only. No perception, hardware validation, or new full 11-skill retention evaluation. See [the full experiment report](report/实验说明.txt), [paired gait plot](report/gait_comparison.png), and [all final results](report/final_results.png).

## Run on the configured server

The scripts are a reproducible snapshot of the configured experiment, **not a self-contained portable installation**. They currently target `/home/pku/frankenmotion`. This branch contains source and compact evidence; weights, original generator assets, GMR/SONIC/mjlab installations and raw traces remain external. Do not expect a fresh clone alone to run. See `dependencies.json` and the previous unified-tracker documentation.

```bash
cd /home/pku/frankenmotion
work/g1_sim_env/bin/python work/gait_run_demo_20261005.py   --name new_gait_demo_001 --seed 76005001 --count 1
```

Use a new output name. Optional `--table-x` / `--table-y` specify known table centre coordinates within the demonstrated workspace. The same command with seed 76005000 was smoke-tested separately from the final32 benchmark. Runtime MuJoCo3.5.0 is required for the exact saved binary model.

## Source map

- `work/table_goal_adapter_20261005.py`: existing learned distance/direction conditioning.
- `work/gait_generate_scenes_20261005.py`: generation and bounded same-noise input-command refinement.
- `work/table_prepare_reference_20261005.py`: GMR and explicit scene-aware hand IK.
- `work/gait_retime_20261005.py`: walking-reference time resampling.
- `work/gait_collect_teachers_20261005.py`, `gait_collect_dagger_20261005.py`, `gait_distill_20261005.py`: selected training method.
- `work/gait_simulate_20261005.py`, `gait_cpu_evaluate_20261005.py`: GPU and independent CPU online control.
- `work/gait_metrics_20261005.py`, `table_audit_rollout_20261005.py`: gait/contact checks.
- `work/gait_run_demo_20261005.py`: one-command generation, reference preparation, control, audit and rendering.
- `gait_train*`, `gait_contact_reference*`, `gait_sonic*`: exploratory alternatives; not the selected deployment pipeline.

Historical pipeline/train scripts intentionally require new output folders and reference archived server assets. They are not idempotent setup scripts. Keep frozen results intact when reproducing.
