# HDM05 sidestep 来源修复（2026-10-10）

本轮仅处理sidestep，其他任务按用户要求暂缓。候选34条训练/6条验证，来自10/2个原始录制；训练清单只含右侧镜像，原生左侧另存参考。未启动训练，等待用户复核10条来自不同训练录制的视频。

## 来源和边界

仅使用HDM05 01-01录制中的非交叉左侧步，对应官方脚本第6阶段与walkLeft类语义，排除圆弧走、右侧交叉步、转身和普通前后行走。[官方录制脚本](https://resources.mpi-inf.mpg.de/HDM05/01-01/index.html)与[分类表](https://resources.mpi-inf.mpg.de/HDM05/cuts/index.html)分别保存动作设计与类别依据。

官方mocapTakes2Cuts映射在2026-10-10返回403，因此本轮边界为根据脚本和实际身体侧向轨迹恢复的补标，不是已经核验的官方walkLeft2Steps/3Steps裁剪行。可用BABEL帧级act_cat标注保留在recovered_events.json作旁证。不能把仅有场景名本身视作类别准入。

13个实际可用原始录制中，10个train、2个val被处理；1个test仅列入排除清单，没有读取动作。每个非测试录制恰好找到一个持续左侧、脚不交叉的候选阶段。以踝间距局部最小值恢复迈开—并拢周期，最终保留40周期；bk01-01 take03的初始周期因转身和前后位移被拒绝。拒绝原因在左右检查中分别计数，因此audit.json中每项出现2次，实际被拒的非测试周期只有1条。

## 方向和镜像

当前sidestep任务5的度量是身体右侧位移。因此保留原始左侧动作供审计，镜像右侧才进入原有训练入口；没有将左侧正距离误当成右侧标签，也没有改动任务定义。

镜像在原始SMPL22关节姿态与根平移执行，交换左右关节并对轴角作相应符号反射，再重新生成20fps的完整205维特征。镜像两次严格恢复原始体姿态与平移；旋转反射矩阵和行列式测试通过。固定骨架左右轻微不对称，镜像后重新测量控制量，不拷贝原始左侧标签。没有额外幅度缩放、重定时或补帧。

原始左侧索引用sidestep_native_left_reference、ready_for_training=false，缓存task=-1，不能被现有sidestep筛选器误加载。镜像与原始共享family和split，其他19类清单逐条完全不变。

- 80个左右缓存均与各自完整源动作的切片精确一致；全部40右侧训练/验证量重算通过，左右参考控制量最大数值差2.87e-8。
- 原始输入/镜像输入、文本CLIP及PCA、局部文本掩码、所有20类family split隔离核验通过。
